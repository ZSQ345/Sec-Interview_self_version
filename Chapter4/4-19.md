### 找到一个注入点怎么判断对方什么数据库

数据库的种类不少，但**不用记五套**。实战里按一条链路走下来，三步就能定下来。

---

## 第一步：有报错就直接读

最省事的情况。网站没处理错误信息，数据库的报错会原样丢在页面上。

| 报错长这样 | 是 |
|---|---|
| `You have an error in your SQL syntax; check the manual that corresponds to your MySQL server version` | MySQL / MariaDB |
| `Microsoft OLE DB Provider for SQL Server`、`Incorrect syntax near` | SQL Server |
| `ORA-01756: quoted string not properly terminated`、任何 `ORA-` 开头 | Oracle |
| `PostgreSQL query failed: ERROR: parser:`、`unterminated quoted string` | PostgreSQL |
| `SQLite3::query(): Unable to prepare statement`、`SQLite format 3` | SQLite |
| `Microsoft JET Database Engine`、`Syntax error in INSERT INTO statement` | Access |

**有报错就到这儿为止，别往下试了。** 剩下两步是给盲注用的。

---

## 第二步：打 sleep 家族，一次分流九成

没有报错就要靠**响应时间**。四种数据库各有一个延时函数，挨个打一遍：

| payload | 响了说明是 |
|---|---|
| `sleep(5)` | **MySQL** |
| `pg_sleep(5)` | **PostgreSQL** |
| `waitfor delay '0:0:5'` | **SQL Server** |
| `dbms_pipe.receive_message('a',5)` | **Oracle** |

每个后面记得跟注释符收尾，比如 `and sleep(5)-- -`。

**四个都不响** → 是没有延时函数的库，SQLite、Access 都是这一类。那就退回第三步按语法差异判。

**这一步最值钱。** 花四次请求，就能把五个库里定掉四个。

---

## 第三步：用「一个字的差异」确认

只剩下一组分不清的时候，用下面的差异点分辨。**不用全记，记加粗的那几个就够了。**

| | MySQL | SQL Server | Oracle | PostgreSQL |
|---|---|---|---|---|
| **`#` 行内注释** | **能用** | 不能 | 不能 | 不能 |
| **字符串拼接** | `concat('a','b')` | `'a'+'b'` | `&#124;&#124;` | `&#124;&#124;` |
| 版本函数 | `version()` | `@@version` | `v$version`（需权限） | `version()` |
| **当前用户** | **`user()`** | `system_user` | **`user`（不带括号）** | `current_user` |
| 当前库 | `database()` | `db_name()` | `ora_database_name` | `current_database()` |
| 取前 n 行 | `limit 1` | `top 1` | `rownum<=1` | `limit 1` |
| 查表清单 | `information_schema.tables` | `information_schema.tables` | `all_tables` / `user_tables` | `information_schema.tables` |

### 三个最省事的判据

1. **`#` 能不能用** → 能用就是 MySQL。这一条最快，因为它只占一个字符，而且不用管闭合。
2. **拼字符串用 `+` 还是 `||`** → 用 `+` 是 SQL Server；用 `||` 是 Oracle 或 PostgreSQL。
3. **当前用户后面有没有括号** → `user()` 带括号是 MySQL，`user` 不带括号是 Oracle。

顺着这三条下来，基本都能定住。

---

## 几个容易踩的坑

**一、`#` 不是所有库都有。** 常见说法是「MySQL/PostgreSQL 都用 `#`」，这是错的。`#` 是 MySQL 独有的，PostgreSQL 里打 `#` 直接语法错误。

**二、`'a'+'b'` 在 MySQL 里不是拼接。** MySQL 会把 `'a'` 和 `'b'` 转成数字 0，结果是 0。MySQL 拼字符串只能 `concat()`。

**三、Oracle 查 `dba_tables` 可能报「表不存在」。** 那是权限问题，不是「不是 Oracle」。普通用户只能查 `user_tables` / `all_tables`。

**四、「延时没响」不等于「不是这个库」。** 可能被 WAF 拦了，可能函数被黑名单了，可能是时间盲注走不通的注入点（比如堆叠查询不支持）。遇到这种情况要换个思路，别直接排除。

**五、报错里带版本号，顺手就收集。** MySQL 5.x 没有 `information_schema` 里的某些列，`5.7` 以上才有 JSON 函数。版本号影响后面怎么打，别只看库名。

---

## 顺带说一句概率

实战里遇到最多的是 **MySQL**，其次是 **SQL Server**（尤其是 .NET 站点）和 **Oracle**（政企、金融老系统）。PostgreSQL 在 Web 站点不算常见，SQLite 多见于小站、客户端软件和 CTF。

判断优先级就按这个来：先打 MySQL，不响再试 SQL Server，再 Oracle，最后才考虑 PG 和 SQLite。
